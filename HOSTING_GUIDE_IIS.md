# How to host the Lab Feedback Form on a Windows VM (IIS)

This guide is for the IT team. It explains, step by step, how to put this app online on a Windows server with IIS.

---

## First: why there is no "HTML" option

This app is **not a plain HTML website**. It is a **Python web app**:

- The HTML pages are in the `templates` folder, but they are **not opened directly**.
- Python (`app.py`) checks the login IDs, decides which lab staff each person sees, and **saves the responses**.
- If only the HTML files are hosted, the pages open but nothing can be submitted.

**IIS Manager has no "Python" option to select.** The file **`web.config`** is what makes it Python.
When IIS sees `web.config` in the site folder, it starts Python and Python serves every page.

| Question | Answer |
|---|---|
| What is the main file? | **`app.py`** is the app. **`web.config`** tells IIS to run it. Both must be in the site's main folder. |
| Is there an `index.html`? | **No.** The home page is generated by `app.py`. Visiting the site opens the login page automatically. |
| What do I choose instead of "HTML"? | Create a normal website in IIS Manager and point it to the folder. `web.config` handles the rest. If your hosting panel only offers "Static / HTML", create the site directly in **IIS Manager** instead. |

---

## What you need (all free)

1. **Windows Server** with **IIS** turned on (it already is if you host other sites)
2. **Python 3.12 or newer** (3.14 is fine): https://www.python.org/downloads/windows/
3. **HttpPlatformHandler v1.2 (x64)**: a free Microsoft add-on for IIS that lets IIS run Python
   https://www.iis.net/downloads/microsoft/httpplatformhandler

**Quick check of what the VM already has.** Copy the app folder to the VM, open **PowerShell as Administrator** in that folder, and run:

```
powershell -ExecutionPolicy Bypass -File .\check_server.ps1
```

It only **reads**, it changes nothing. It shows `[ OK ]` or `[FAIL]` for IIS, HttpPlatformHandler, Python, the app files,
the venv, the IIS site and pool settings, and folder permissions. Each `[FAIL]` line says how to fix it.
Run it again after each step until everything is OK. After the site is up, add `-TestUrl "https://<your-site-address>/login"` to also test the live link.

## Step 1: Install Python

*(Skip this step if Python 3.10 or newer is already installed **for all users**. The checker tells you.)*

1. Run the Python installer (64-bit, version 3.12 or newer).
2. Click **Customize installation** and tick **"Install Python for all users"**.
3. Tick **"Add Python to environment variables"**.
4. Finish the installer.

To check it worked, open **Command Prompt** and type `py --version`. It should print `Python 3.12` or newer.

## Step 2: Install HttpPlatformHandler

1. Download **HttpPlatformHandler v1.2 (x64)** from the link above and install it.
2. Open **Command Prompt as Administrator** and run `iisreset`.

## Step 3: Copy the app folder

1. Create the folder **`E:\labfeedback`**.
   *(If you use a different folder, open `web.config` and change the 2 paths marked "CHANGE IF NEEDED".)*
2. Copy these items into it:

```
app.py
icons.py
workbook_utils.py
requirements.txt
web.config
static\        (whole folder)
templates\     (whole folder)
```

3. Create an empty folder called **`logs`** inside it.

**Do not copy** `__pycache__`, `data received`, or any Excel files with real data.
Copy the `instance` folder **only** if you are moving an existing live setup. It holds the database and the secret key.

## Step 4: Install the app's packages

Open **Command Prompt as Administrator** and run these lines one at a time:

```
cd E:\labfeedback
py -m venv venv
venv\Scripts\pip install -r requirements.txt
```

This creates a private Python environment (the `venv` folder) just for this app.

## Step 5: Set the admin password

```
venv\Scripts\python app.py reset-admin
```

It prints something like `Username: admin  Password: xxxxxxxxxxxx`.
**Write it down and give it to the app owner.** Run the command again if the password is ever lost.

## Step 6: Create the website in IIS Manager

1. Open **IIS Manager**.
2. **Create an Application Pool**: right-click **Application Pools**, then **Add Application Pool**
   - Name: `LabFeedback`
   - .NET CLR version: **No Managed Code**
   - Click OK
3. Select the new pool, click **Advanced Settings**, and set:
   - **Idle Time-out (minutes)** = `0` (stops the site from going to sleep)
   - **Maximum Worker Processes** = `1` (**must stay 1**)
   - *(optional)* **Start Mode** = `AlwaysRunning`
4. **Create the website**: right-click **Sites**, then **Add Website**
   - Site name: `LabFeedback`
   - Application pool: **LabFeedback**
   - Physical path: `E:\labfeedback`
   - Binding: **https**, port 443, host name such as `labfeedback.upes.ac.in`, and select the SSL certificate
   - Click OK

**This server also runs another website (a dashboard).** Keep the two apart:
- Create this as a **separate website**, not as an Application under the dashboard site. The app does not support running under a sub-path like `/labfeedback`.
- Give it **its own host name** (for example `labfeedback.upes.ac.in`) or its own port. Two sites cannot share the same host name and port.
- The `iisreset` in Step 2 restarts **all** sites for about 5 to 10 seconds. Do it at a quiet time.

## Step 7: Set folder permissions (the app saves data, other sites stay out)

On a data drive like E:, Windows lets **every** signed-in account read and change new folders by default, and that includes the other website's app pool.
These commands lock the folder so that **only Administrators, SYSTEM and this app** can use it, and let the app save responses and logs.
In **Command Prompt as Administrator**:

```
cd E:\labfeedback
if not exist instance mkdir instance
icacls . /inheritance:r /grant:r Administrators:(OI)(CI)F SYSTEM:(OI)(CI)F "IIS AppPool\LabFeedback":(OI)(CI)RX
icacls instance /grant "IIS AppPool\LabFeedback":(OI)(CI)M
icacls logs /grant "IIS AppPool\LabFeedback":(OI)(CI)M
```

## Step 8: Open the link

| Page | Link |
|---|---|
| Students and Faculty | `https://<your-site-address>/` |
| Admin | `https://<your-site-address>/admin/login` |

The first visit can take 5 to 10 seconds while Python starts. After that it is fast.

**Then:** the app owner logs in as admin, uploads the master Excel file, and shares the main link with students and faculty.

## Step 9: One check after it is live

The app blocks a computer for 15 minutes after 20 wrong IDs. To make sure it blocks the **right** computer, check that it sees each visitor's real IP address:

1. Log in once on the site, as a test user or as admin.
2. On the server, run:

```
cd E:\labfeedback
venv\Scripts\python -c "import sqlite3; print(sqlite3.connect('instance/feedback.db').execute('select at, actor, ip from audit_log order by id desc limit 3').fetchall())"
```

- **Good:** the `ip` column shows real addresses (for example `10.x.x.x`).
- **Problem:** it shows `127.0.0.1` for everyone. Then one person's mistakes would block **all** users. Tell the app owner so it can be fixed before sharing the link.

## Daily care

| Task | How |
|---|---|
| **Backup** | Copy the `instance` folder daily. It contains **all responses**. |
| **Update the app** | Replace the `.py` files, `static` and `templates`. **Never delete `instance`.** Then recycle the `LabFeedback` application pool. |
| **Restart** | IIS Manager, then Application Pools, then LabFeedback, then **Recycle** |
| **Errors** | Read `E:\labfeedback\logs\python.log` |

## If something goes wrong

| What you see | Likely reason | Fix |
|---|---|---|
| **HTTP Error 500.19** | HttpPlatformHandler is not installed | Do Step 2, then run `iisreset` |
| **HTTP Error 502.3** or the site never loads | Python failed to start | Read `logs\python.log`. Usually the Python path in `web.config` is wrong, or Step 4 was skipped. |
| Nothing is written to `logs\python.log` | No permission | Do Step 7 again |
| "Unable to open database" in the log | No permission on `instance` | Do Step 7 again |
| Login works but people get logged out at once | Site opened over `http://` | Use the `https://` link. For an http-only test, set `LAB_HTTPS` to `0` in `web.config`. |
| Excel upload fails for large files | File is over 10 MB | Split the file, or ask the app owner to raise the limit |

---

## Security notes

- `web.config` blocks downloads of `instance`, `venv`, `logs` and `__pycache__`, so the database and secret key cannot be reached from a browser.
- Use **HTTPS** only.
- Keep the `instance` folder and backups private. They contain student and faculty data.
